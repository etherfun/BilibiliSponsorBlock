# 其他 AI 生成内容检测方式：调研与选型

本文回答一个问题：**除了第一阶段已落地的文本启发式规则，还有哪些路可走，值不值得在浏览器扩展里走。**

选型约束（来自本项目现状）：

- 运行在 B 站页面里的 content script，要**离线、低延迟、低内存**，不能阻塞滚动。
- 扩展已上架 Chrome / Edge / Firefox / Safari，**包体积与商店审核**都敏感。
- 不引入联网或第三方 API 作为默认路径（隐私 + 稳定性 + 账号风险）。
- 用户群体是普通观众，**误伤真人评论的代价远高于漏掉 AI 评论**。

> **关于「整合」的一条设计结论**：新检测能力不应该另起一套机制。
> 「疑似 AICG 内容」现在是已有类别表（`dynamicSponsorSelections`）里的一行，
> 处理方式、标签样式、隐藏交互、白名单、总开关全部复用商品链接那一套。
> 后续接 embedding 或小模型时，只需在 `src/content/aicg/` 里换一个 `AicgDetector` 实现，
> **决策与执行层完全不用改**，设置页也只是多一个开关。

## 1. 文本启发式规则

### 1.1 可用的信号

| 信号 | 实现难度 | 运行成本 | 效果（本地实测，见分析报告 §4） |
|---|---|---|---|
| 关键词/短语命中 | 极低 | 极低 | 对固定人设话术有效，对改写无效；**不可单独使用** |
| 套话/书面语密度 | 极低 | 极低 | 弱，只作辅助 |
| 句长分布（CV） | 低 | 极低 | 弱，真人规范长评同样低 CV |
| 标点使用（种类/熵） | 低 | 极低 | 弱，易受排版习惯影响 |
| 文本重复度（n-gram 新鲜度） | 低 | 低 | 中，对模板化文本有效 |
| 跨评论相似度（Jaccard） | 低 | O(n²)，需限长 | **强** |
| 重复家族聚类（并查集） | 低 | O(n²) 但常数小 | **强**，误报极低 |
| **跨作者长片段复用（8 字窗口）** | 低 | O(n) | **强**，专治改写型（本次新增） |

### 1.2 结论

- **实现难度：低。** 纯 TS，无依赖，全部在 `src/content/aicg/`。
- **运行成本：可忽略。** 一屏 20~40 条评论，构建一次上下文（O(n²) 带长度预筛的并查集 + O(n) 短语统计），重复扫描走 `WeakMap` 去重不做重复计算。
- **实测：默认阈值 0.55 下 precision 100%（0/13）、recall 86.7%**（90 条人工标注样本）。
- **召回上限**：读起来像真人提问/建议的 AI 评论抓不住，需要语义模型。

> 一句话：规则检测是**唯一能在第一阶段安全落地**的方案，擅长「批量/模板/复制事实包」，不擅长「单条高质量改写」。

## 2. NLP 与机器学习

### 2.1 专用 AI 文本检测分类器

现状（2026-11 检索）：

- **TMR / RoBERTa-base 类**有 ONNX 版本可直接跑（`onnx-community/tmr-ai-text-detector-ONNX`），英文 RAID 榜 AUROC 99.28%（含对抗样本）；fp32 权重约 500 MB 级，量化后仍 100 MB+。
- **中文基准 C-ReD**（arXiv 2604.11796）指出中文语料「模型多样性有限、同质化严重」；基于 CNKI 摘要 + DeepSeek R1/Phi4/Qwen2.5 的研究显示，RoBERTa 类对 Phi4 召回可达 100%，但对 **Qwen2.5 只有 88.91% 准确率**——越「像人写」越难判。
- 商用检测器（Copyleaks、Pangram）声称中文 99%+，但**只能走 API**。

| 维度 | 结论 |
|---|---|
| 模型体积 | 轻量中文可用方案最少 20~100 MB 量化，**对浏览器扩展偏大**（当前 content.js 已 2.7 MB） |
| 推理耗时 | 单条 50~200 ms（CPU/WASM），滚动时逐条跑不可接受 |
| 内存占用 | 100~300 MB 常驻，移动端浏览器会换出页面 |
| 中文能力 | **领域错配**：训练在论文/新闻长文，对 60~100 字的 B 站评论、玩梗、emoji、颜文字泛化差 |
| 浏览器可行性 | 技术可行（onnxruntime-web），工程代价大 |
| 是否需联网 | 本地推理不需要，但模型下载本身要联网，且要进商店包 |

**判断：暂时不值得引入。** 短评论 + 玩梗语料是这类检测器最弱的场景。

### 2.2 Embedding 相似度

- 轻量中文 embedding（`bge-small-zh` 量化 ~25 MB，`text2vec-base` ~100 MB）能把「改写过的同一套说辞」聚到一起，正好补 §4.4 的漏检。
- 但浏览器内逐条推理成本与 2.1 同量级；**除非上服务端**。

**判断：第二阶段值得尝试，优先「服务端/可选开关」，不做默认本地推理。**

### 2.3 小型文本分类模型

- 自训 2~8 MB 轻量中文分类器（字符级 CNN / 蒸馏小 BERT）理论上可行，针对性微调效果可能远好于通用检测器。
- 需要：**标注数据**（目前只有 90 条自标注）、训练管线、持续迭代、误报监控。
- 社区同类项目（`dafeiyu-cleaner` 系列）走的也是「离线规则优先 + 可选 LLM 精判」，而不是本地分类模型——这本身说明本地小模型性价比尚未被验证。

**判断：第二阶段值得尝试（若有标注数据），当前不建议。**

### 2.4 可在线运行的 ONNX

技术路径成熟（`onnxruntime-web` + WASM/WebGPU），瓶颈不是「能不能跑」而是**体积与中文短文本效果**。若要试：

- 只在用户点「复核这条」时按需加载（不随包分发）；
- 用 `Web Worker` 避免阻塞主线程；
- 明确标注为实验功能。

## 3. 统计与语言学特征

| 指标 | 理论价值 | 实测/现实 | 结论 |
|---|---|---|---|
| **Perplexity** | 高：AI 文本更「可预测」 | 需要与检测模型同源的语言模型；中文短评论上下文太少，困惑度方差极大 | 理论可行，实际不可靠 |
| **Burstiness** | 高：人写作复杂度波动大 | 与 F7（句长 CV）同源。60 字只有 2~3 句，统计量不足；实测真人规范长评也会低 | 只可作弱证据 |
| **Token 分布/重复模式** | 中 | 中文分词要额外依赖，评论大量非规范写法；退化为字符 n-gram | 已用轻量替代 |
| **句长分布** | 中 | 弱证据 | 已降权 |
| **词汇多样性（TTR）** | 中低 | 短文本 TTR 方差极大 | 不推荐 |
| **句法/LM 特征** | 高 | 需句法分析器，体积与延迟不可接受 | 不推荐 |

**提醒**：这些指标常被营销成「AI 检测器」，但在**短文本 + 中文 + 网络语**条件下独立判别力远低于宣传。本实现只把句长均匀度、标点机械度作为**加权弱证据**，并有闸门防止它们单独越阈值。

## 4. 其他可利用的公开信息

| 信息 | 可用性 | 价值 | 备注 |
|---|---|---|---|
| 评论发布时间与时间分布 | 接口给 `ctime` | **高**：同账号连发 < 20s 是铁证 | 需按作者聚合，第二阶段 |
| 同一用户多条评论 | 按 `mid` 聚合 | **高**：实测 229 条同模板 | 第二阶段 |
| 多条评论文本相似度 | 前端已有 | **高**（F1/F2/F3/F4） | 已落地 |
| 评论与视频内容语义关联 | 需标题/字幕 | 中高：机械复述摘要 | 需 embedding |
| 昵称/头像/简介特征 | 接口给 `member` | 中：鱼/鲸昵称占 37.6% | **谨慎**：可伪装，真人也会跟风改昵称；只作额外弱信号且默认关闭 |
| 账号等级 / IP 属地 / 设备指纹 | 部分可见 | **无关联** | **明确不采用**，见下 |

**明确不用的东西**：账号等级、IP 属地、设备指纹、粉丝数、注册时间。这些既不能可靠指示 AI 生成，又会把「低等级新用户」整体打成可疑——技术站不住，伦理上也不该做。

### 最终技术路线

**第一阶段（已实现）**

1. 规则检测内核（`detector.ts`）：跨评论证据（模板复用、相似度、重复家族、跨作者短语）为主，其余降权。
2. 以「类别」形式接入现有类别表，处理方式 = `DynamicSponsorOption`，执行复用 `SponsorComment`。
3. 强闸门：跨评论证据不足时置信度被压到阈值以下——**保证规范长评不被误伤**。
4. 跳过短评论与口语化评论；跨评论特征要求正文 ≥ 20 字。
5. 默认禁用，升级不影响现有用户；旧版独立设置自动迁移。

**第二阶段（按收益排序）**

1. **同作者聚合信号（F11）**：当前屏按作者聚合，检测「同账号短时间连发同模板」。纯前端、无模型、收益最高。
2. **评论流元数据**：接入 `mid` + `ctime`，做跨视频同模板；注意请求节流。
3. **可选语义复核**：在 `AicgDetector` 后接 `SemanticAicgDetector`，默认关闭；只对「规则判定为边界」的评论调用。
4. **标注数据积累**：用「显示命中特征」+ 用户「这不是 AI」反馈沉淀标注集，再决定是否训小模型。

**暂不值得引入**

- 通用英文/长文 ONNX 检测器（体积大、领域错配）。
- Perplexity / Burstiness 作为主判据（需本地 LM，短文本统计量不足）。
- 账号等级、IP、设备指纹类画像（无因果关联，且伦理上不该做）。
- 默认联网调第三方 API（隐私、稳定性、依赖风险）。

### 已预留的扩展点

```ts
// src/content/aicg/types.ts
export interface AicgDetector {
    detect(input: AicgCommentInput, context?: unknown): AicgDetectionResult;
}
```

`AicgCommentInput` 已包含 `peers`、`peerAuthors`、`author` 等上下文字段。接 embedding / 小模型 / 服务端精判时，**决策层与执行层不需要改动**：`decideAicgOption` 只认 `confidence` + `option`，`SponsorComment` 只认最终选项。
